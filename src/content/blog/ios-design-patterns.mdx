# 🧩 Creational Design Patterns
Creational patterns focus on object creation, controlling how objects are constructed and instantiated.
---
##  **Singleton Pattern**

### **Intent**

Ensure only one instance of a class exists and provide a global access point.

### **UML Flow**

```
+--------------+
|  Singleton   |
+--------------+
| instance     |◄───────── ensure only one instance
+--------------+
| shared()     |
+--------------+
```


### **When to Use**

* Shared resources (e.g., UserDefaults, API clients, Session managers).

### **iOS Example**

```swift
final class NetworkManager {
    static let shared = NetworkManager()
    private init() {}
}
```


---
## **Factory Pattern**

### **Intent**

Create objects without exposing creation logic.

### **UML Flow**

```
Client(Creator) → Factory → Concrete Product
```


### **When to Use**

* Creating objects with complex initialization.
* Switching behavior based on configuration.

### **iOS Example**

```swift
protocol ScreenFactory {
    func makeMovieDetails() -> UIViewController
}
---
protocol Payment { func pay() }
class Visa: Payment { func pay() {} }
class PayPal: Payment { func pay() {} }

struct PaymentFactory {
    static func make(_ type: String) -> Payment {
        type == "visa" ? Visa() : PayPal()
    }
}

```

##  **Builder Pattern**

### **Intent**

Construct objects step by step, especially when initialization is complex.

### **Flow**

```
Director → Builder → Product
```


### **Example**
Used often for
- URLRequest configuration.
- Creating complex view setups
- Creating JSON request bodies

```swift
let builder = URLRequestBuilder()
    .set(method: .get)
    .set(url: "/movies")
    .addHeader(key: "Auth", value: token)
```

# Structural Design Patterns
Structural patterns focus on how objects are composed.
---
##  **Adapter Pattern**

### **Intent**

Convert one interface into another.

### **Flow**

```
Client → Adapter → Adaptee
```


- Use Case
  - Wrapping an old API to work with new code
  - Convert JSON into your app model

### **iOS Example**

```swift
class LegacyAPI {
    func fetch() {}
}

protocol DataProvider {
    func loadData()
}

class LegacyAdapter: DataProvider {
    private let legacy = LegacyAPI()
    func loadData() { legacy.fetch() }
}
```

# Behavioral Design Patterns
These patterns focus on how objects communicate.

---
## **Coordinator Pattern**

### **Intent**

Handle navigation logic outside UIViewController.

### **Flow**

```
App → Coordinator → Child Coordinators → Screens
```


### **Example**

```swift
protocol Coordinator {
    func start()
}
```


---
##  **Strategy Pattern**

### **Intent**

Switch between algorithms at runtime.

### **Flow**

```
Context → Strategy
```


### **Example**

Sorting strategy, payment method selection.

---
##  **Observer Pattern**

### **Intent**

Notify multiple observers when state changes.

### **Flow**

```
Subject → Observer1
        → Observer2
```


### **iOS Example**

* NotificationCenter
* Combine publisher → subscribers

```swift

```

##  **MVVM Pattern**

### **Intent**

Separate UI logic from business logic.

### **Flow**

```
View ↔ ViewModel ↔ Model
     ┌──────────┐
     │   View   │
     └─────┬────┘
           │ Binding
     ┌─────▼──────┐
     │ ViewModel   │
     └─────┬──────┘
           │
     ┌─────▼──────┐
     │   Model     │
     └─────────────┘

```


### **iOS Example (SwiftUI)**

```swift
class MoviesViewModel: ObservableObject {
    @Published var movies = []
}

struct MoviesView: View {
    @StateObject var vm = MoviesViewModel()
    var body: some View { List(vm.movies) { ... } }
}
```

# Clean Architecture

```
Presentation → Domain → Data → External
 UI (SwiftUI/VC)
        │
        ▼
 Presentation (ViewModels)
        │
        ▼
 Domain (UseCases + Entities)
        │
        ▼
 Data (Repository + DataSources)
        │
        ▼
 External (API, Database)

```


- Benefits
  - Use cases layer
  - Highly testable
  - Dependency rule: flow only inwards
