Building a SwiftUI app is fun at first. Models are lightweight, views are declarative, and previews make iteration fast. But as the app grows past a few screens, the codebase starts to fight back. That's when a deliberate architecture pays off.

## Keep Views Dumb

A view should render state and forward user intent — nothing more. If you find yourself writing network calls or decoding JSON inside a view body, stop. Extract that logic into an observable model or a dedicated service.

```swift
struct ContentView: View {
    @StateObject var model = ContentModel()

    var body: some View {
        List(model.items) { item in
            ItemRow(item: item)
        }
        .task { await model.load() }
    }
}
```

The view owns almost nothing except presentation. Testing the view becomes trivial, and the model is easy to unit test in isolation.

## Group Code by Feature

Flat folders of `Models/`, `Views/`, and `Services/` work for small apps but scale poorly. Once a feature touches all three, navigation and review get harder. Instead, group everything that belongs to one feature together:

```
Features/
  Profile/
    ProfileView.swift
    ProfileModel.swift
    ProfileAPI.swift
```

Dependencies between features should be explicit and small. When one feature imports another, it should feel like a deliberate decision, not an accident.

## Make State Changes Predictable

Whether you choose MVVM, Redux, or something in between, the important thing is a single, obvious path for state changes. Prefer a few well-named methods on a model over ad-hoc mutation from multiple views. It makes bugs reproducible and fixes reviewable.

## Start Simple

Architecture is a tool, not a trophy. Start with plain `@StateObject` and feature folders. Introduce heavier patterns only when the pain justifies them — the team will thank you.
